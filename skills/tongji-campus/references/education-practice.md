# 本人实践完成情况与成绩

适用：查询本人社会实践、劳动教育相关实践的完成情况、理论成绩、认定学时和最终成绩。官方本科教务入口 `https://1.tongji.edu.cn/#/inquiryResults`。使用官网页面流程读取。

## 操作流程

1. 复用教务登录状态，打开本人“成绩查询/实践成绩”对应页面。优先读取学生本人视图，不从管理端的全体学生列表搜索；页面必须与实际请求的课程/实践项目相符。
2. 等待理论成绩、实践学时和最终成绩区域加载，读取页面明确给出的要求、已认定数和完成标记。若当前视图未加载明细，只展开本人相关栏目。
3. 需要解释学时计算时，读取当前页面规则和本人明细；把理论成绩、必修完成情况、选修认定学时、最终等级分开汇报。用户只要结果时，不必重建整套学校评分规则。
4. 已有正式最终成绩时按官网显示回答；没有最终成绩但学时达标时，只说学时达标，不能代推最终等级。不触发页面的“计算&同步成绩”、编辑、导入或提交功能。

教务认证方式见 [本科教务](education.md)。普通 CLI 的读取白名单只包含课表相关接口；实践查询使用浏览器或针对目标页面的辅助读取。确需请求辅助读取时，仅在本地使用现有教务凭据，按当前官网前端核实的路径、参数读取本人数据并投影必要字段；不把会话对象、学号或姓名输出给模型，不猜接口路径。

## 已确认的解释要点

官方页面的实践成绩组件包含以下函数，可在页面变更后用这些名称定位相关代码，无需重新全文分析整个教务前端：

| 前端函数 | 作用 |
| --- | --- |
| `LaborEducationList` / `LaborEducation` | 读取各板块学时要求和总要求 |
| `theory` / `labourTheoryScorelist` | 当前学生的理论成绩 |
| `TheoryDetails` / `queryFinalDetail` | 当前学生各板块实践明细 |
| `Scorelist` / `queryFinalResultlist` | 最终成绩列表，学生范围必须由身份和页面确认 |

实践明细以 `plateId` 标识板块，`nature==1` 区分必修板块，其他为选修板块。同一板块多条记录先相加，选修认定值还会按该板块配置上限截断，再汇总比较选修总要求。因此“活动原始学时总和”可能大于“课程认定学时”，不能把两者混用。例如某选修板块有 12 学时、规则最多认定 8 学时，那么在选修达标计算中计入 8 学时。

按当前页面规则计算完成情况；缺少任何必修板块的明细不能仅凭总学时判定全部完成。字段含义不明确时保留原名说明待核实，不把 `score` 等数值直接映射成“优”。

## 避免重复探索

先进入 `/#/inquiryResults` 和本人视图，不先遍历全校菜单或管理模块。只在页面缺失必要信息时读取相关组件；前端压缩文件应按上述函数提取短片段，不输出整包代码。一次得到完整结果后即可结束，不因普通课表 CLI 不含成绩命令而反复重新登录，也不为查询而执行任何成绩更新操作。
