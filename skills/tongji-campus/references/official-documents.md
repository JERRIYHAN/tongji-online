# 官方电子文件目录与下载导航

用户需要官方成绩单、在读证明、出入境证明、成绩计算方式证明、奖学金文件时，先查本文件。站点名称为“自助打印／自助打印移动办理平台”，既包含电子件业务，也包含纸质打印、取件等功能，不能仅凭“打印”二字判断它不支持电子文件。

## 入口

- 官方目录：`https://zzfw.tongji.edu.cn/wec-self-print-app-console/mobile.html#/mobile/itemList`。
- 应用路径前缀：`/wec-self-print-app-console`。复用学校统一认证，在官网内完成文件获取流程。
- 下面目录更新于 2026-10；当前账号可用项目与资格由官网给出，需要其他证明时刷新目录或搜索相关名称。

## 网站位置

主要页面路由如下。完整网址均为入口中的 `mobile.html#` 后拼接对应路由。

| 功能 | 路由 | 使用要点 |
| --- | --- | --- |
| 证明文件目录 | `/mobile/itemList` | 搜索框、标签筛选、项目名称及“预览”按钮 |
| 文件详情 | `/mobile/orderDetail?id=<项目ID>` | 项目 ID 来自当次目录；不可猜测，也不要跳过正常流程直达 |
| 创建订单 | `/mobile/orderCreate` | 由官网流程传入项目 ID 和获取方式，不手拼业务参数 |
| 未完成任务 | `/mobile/orderListUnCompleted` | 底部“未完成”；处理模糊结果、重复申请提示时查看本人相关任务 |
| 已完成任务 | `/mobile/orderListCompleted` | 底部“已完成”；是否能重取电子件以实际页面为准 |
| 登录 | `/mobile/login` | 由官网决定登录入口，优先复用统一认证；仅页面要求时请本人扫码 |

不要把此目录混入教务 `1.tongji.edu.cn` 左侧菜单；它是独立网站。教务里的“我的成绩”用于查询成绩，官方电子成绩单优先到本网站的对应目录项目。

## 查询目录的最短流程

1. 优先复用已有的、可控的 zzfw 登录页面。没有时用校园助手现有浏览器辅助恢复学校认证，并打开上述完整目录入口。按当前宿主权限启动浏览器。
2. 以目录名称出现作为页面已就绪的判断，避免对每步固定等待网络完全空闲。初始页面可能短暂为空；先等列表或登录提示，不把短暂空白解释成无文件或已失效。
3. 读取当前目录、搜索或筛选结果。仅列目录时，到这里即可结束，**不要点“预览”**。当前页面的搜索框为“输入关键字进行搜索”，另有标签筛选。
4. 结果只输出项目名称、标签及必要的业务配置；不输出完整用户信息、Cookie、浏览器存储、请求头或带认证参数的跳转网址。
5. 当前浏览器上下文应贯穿一次任务。`withBrowser` 回调期间持有本地状态锁，不再并行启动使用相同 `TONGJI_CAMPUS_HOME` 的其他校园脚本；完成后正常关闭上下文。

该服务使用自己的会话，不能把教务的 `X-Token`、Canvas 凭据或图书馆凭据发给它。当前 CLI 持久化范围未包含 zzfw 独立会话；连续任务复用浏览器，新上下文从官方入口恢复认证。

## “预览”按钮的实际行为

这是本网站最需要记住的操作差异：目录组件 `giAh.toFileDetails` 点击“预览”后，先检查次数限制，再执行 `qualification`。`qualification` 会向 `/order/create` 发送请求，包含 `apiType:1` 等资格校验参数，随后才进入文件详情。

“预览”会经过创建订单接口。仅列目录时停在目录；用户要取得文件时沿正常预览、资格校验和详情流程继续。

## 用户以后明确要求下载某份文件时

按以下流程取得用户需要的文件：

1. 确定文件种类、语言及范围，使用上表精确定位。用户明确要求“下载中文成绩单”已覆盖取得这份文件所需的正常生成步骤，不为免费、必要的步骤重复索取确认；范围缺失且会影响输出时再问。
2. 通过项目“预览”进入资格校验与详情；若提示已有申请，先查看本人相应未完成任务，不反复申请或擅自取消旧任务。
3. 根据官网表单选择必需参数。按项目当前表单处理语言、用途或课程范围等参数。
4. 在“选择文件获取方式”中选择“电子档下载”，不要误选取件码或纸质打印。前端会按项目获取方式配置决定按钮是否显示；按钮缺失不代表应该强行调用下载接口。
5. 官网接着进入创建订单和结果流程。核实费用、配额、资格提示；若出现未被用户授权的收费或向外部邮箱发送文件，先说明具体金额或收件人并取得授权，再继续对应动作。纯下载授权不包含发送邮件。
6. 提交结果不明时先检查本人相关任务，确认是否已生成；不要盲目重复提交。资格不足、无数据或配额限制按官网提示报告，不把失败说成“没有这份文件”。
7. 下载到用户授权的本地位置后，确认文件实际存在、类型及内容对应目标项目，返回本地文件链接。浏览器出现“申请成功”或下载链接，不等于本地已经收到文件。仅为交付文件时不把成绩单全文再次输出到聊天。

如果使用现有 `withBrowser` 辅助执行真正下载，需要为该次任务创建允许下载的上下文并处理浏览器下载事件；当前公共辅助默认 `acceptDownloads:false`。使用浏览器下载事件保存文件并核对实际产物。

## 已确认的读取协议与排错线索

仅在需要刷新目录或诊断页面变化时参考；优先让正常官网页面处理登录和请求，避免每次重新分析前端。以下接口路径均相对于应用前缀 `/wec-self-print-app-console`。

| 用途 | 方法和相对路径 | 证据与注意点 |
| --- | --- | --- |
| 目录列表及子级列表 | POST `/item/sp-print-item/list/terminal` | 目录页面实际加载；前端 `query`、`searchChildrenFile` 共同使用 |
| 标签列表 | GET `/item/itemTag/list/terminal` | 目录组件 `getTag` 使用；标签显示名字段为 `tagContent` |
| 文件配置详情 | GET `/item/sp-print-item/terminal/<项目ID>` | `getFileDetail` 使用；只从当前目录取得 ID，按目标项目需要读取 |
| 电子件入口开关 | GET `/mobile/getDict/MOBILE_CONFIG/USE_DOWNLOAD` | 目录前端 `getDownloadState` 使用；不代表每个项目都可下载 |

前端目录请求使用 **`application/x-www-form-urlencoded` 表单编码**，不是 JSON；字段为 `name`、`state:"1"`、`tagId`、`rows:5000`、`page:1`，子目录按 `parentId` 查询。响应的目录数组位于 `data.records`，正常业务码为字符串 `"0000"`；HTTP 200 不能代替业务成功判断。结果有分页/总数字段时检查是否读取完整，不把第一页说成全量。列表只保存项目名、标签、项目 ID 等必要字段，不能把原始响应整包放进 skill。

官网请求设置 `X-Requested-With:XMLHttpRequest`、`appId:80019`、`LoginMode:MOBILE`，同源请求携带网站自身 Cookie。业务码 `4101`、`9100` 会触发前端转登录；不能把所有错误都归因为登录过期。目录使用表单编码；误用 JSON 时可能返回 `9999`，改正编码后再读取。

以下属于生成或交付流程，不是目录读取白名单：`/order/create`、`/order/download/<订单ID>`、`/message/sendElectronicItemEmail`，以及付款、取消订单等接口。不要根据 GET/POST 方法判断是否有业务副作用，例如发送邮件也可能由 GET 触发。用户只要求探索目录时不调用这些接口。

前端定位线索：移动端入口 `mobile.html` 实际加载的脚本及其 manifest；目录组件 `giAh`、文件详情组件 `etKN`、移动端接口模块 `T5M0`。资源文件名带版本哈希，下次以当前页面为准，使用当前资源版本。检查时只提取这些组件的相关函数，不输出整包组件库或内嵌图片数据。
