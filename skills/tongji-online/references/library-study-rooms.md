# 图书馆研习室：目录、时段与申请流程

用户问单人／多人研习室、讨论房间、房间空闲时间或预约时，读本文件；查区域普通座位或月度研修／考研座位时读 [座位文档](library-seats.md)。同一官网可能显示“研习室”“研讨室”“空间预约”等文字，按功能和房间类型识别，不因名称不同绕到另一个网站。

目录定位见 [研习室房间目录](library-study-rooms-catalog.md)。研习室通过浏览器操作，读取协议见下文。

## 界面树与最短路线

```text
首页 /home
├─ 座位预约 /SeatScreening/1
│  └─ 座位类型：普通座位 / 研修座位 / 考研座位
├─ 研修座位、考研座位：进入上面的座位界面并预置类型筛选
└─ 研习室预约 /SeatScreening/2
   ├─ 筛选：空间名称、馆舍、楼层、空间类型、日期、时间、噪音、人数、特征
   ├─ 列表：房间卡片 → 房间详情 → 预约
   └─ 快速选择：日期 → 馆舍 → 楼层 → 区域 → 进入房间预约页
       └─ 房间标签、查看区域详情／平面图、日期、时间滑块
           └─ 确定选择 → 申请表 → 立即预约（真正提交）
```

所有路由位于 `/h5/#` 后。桌面列表会自动打开第一页第一个房间的详情；**列表仅加载 10 条不代表只有 10 个房间**，显示总数与分页读取分开核对。

研习室筛选配置列 4 种空间类型：单人研讨室 `2`、大型研讨室 `5`、多人研讨室 `6`、开放研讨室 `7`。房间目录快照见子文件。不同房型可采用不同时间选择和申请表，按目标房间页面继续探索。

### 只查房间和空闲时段

1. 确定馆舍、日期、人数和需要的时段。只查目录时不必要求用户提供预约用途和其他人学号。
2. 保持一个已认证的浏览器上下文，从首页点“研习室预约”。使用房间全名和馆舍定位，同名“202”可能在嘉定和沪北同时存在。
3. 按需求选馆舍、空间类型／人数等筛选；读列表或已确认的目录请求。只问有哪些房间，到这里即可结束，不逐房间打开。
4. 查询目标房间时，打开详情核对容量、类型和权限，再点详情的“预约”进入日期／时间页。**这一处“预约”仅进入选择页面**，与申请表的“立即预约”区分。
5. 按房间实际日期数据、开放边界、不可用区间及最短／最长时长判断能否满足用户。只查询时不必点“确定选择”，更不用填写申请表。
6. 报告具体房间、日期、时间、人数限制和查询时间；跨日期切换后读右侧实际选中日期，不能照抄仍保留的左侧列表日期。短暂空白或按钮禁用不等于全馆没有房间。

同一个房间页面顶部可切换邻近房间；例如嘉定二楼显示 202–215 共 14 个单人房间标签，沪西多人房间只显示自身。换房间后重新读取人数、日期和时段，不能复用上一间的数据。

### 用户以后明确要求预约时

在已有预约授权范围内，通过正常官网继续；先补齐真实日期、时长、房间／可接受替代项、使用人数、用途以及页面必需的参与者信息，不凭空写主题、研究内容或学工号。

1. 在房间日期／时间页选有效范围，核对开始小于结束、无不可用区间冲突并满足时长规则。例如接口 `minTime:60,maxTime:240` 对应 1–4 小时，使用当前房间配置。
2. 点击底部“确定选择”（部分组件默认文案“确认选择”）。该按钮传递选择结果并导航到申请表。
3. 申请表包含申请人、预约时间、房间、成员学工号及“添加”、参与成员、申请主题、申请内容、联系电话、“是否公开”等。按用户真实用途填写；不将预约设置为公开作为默认决定，也不擅自改变用户选择。电话只在学校表单内使用，不输出到聊天或 skill。
4. 多人房间可能要求其他成员。沪西多人研讨室01人数配置为 2–6，申请表显示可添加 1–5 人，即上限通常包括申请人；最终按目标房间的当前人数和资格校验。不要为凑人数读取通讯录或随意查他人信息。
5. 设备、上传附件、固定主题选项是否出现取决于房间配置；按页面要求准备真实业务材料。
6. 申请表的**“立即预约”才会提交**：当前普通日内房间分支调用 `/reserve/index/confirm`，有官网加密处理；不手工仿造写请求。月历／周期或大空间有其他提交分支，不复用普通座位 `/api/Seat/confirm`。
7. 以官网结果及必要时本人对应预约记录确认地点、时段、成员和状态。审批中不等于已获准使用；超时或结果不明先核对记录，不能重复提交。不要为探索或清理状态取消已有预约。

快速选择面板也有叫“立即预约”的按钮，前端连接的是进入选择页的导航；仅凭相同按钮名无法判断副作用。每次结合所在页面与当前处理函数判断，探索时无需点击最终申请表按钮。

## 官网规则快照

入口：顶部“预约规则 → 研讨室预约”。规则更新时间：2026-10。

- 可预约 3 日内；须通过学校统一身份认证。全局筛选和单间可选日期可能不同，使用目标房间的日期数据。
- 要填写预约主题、预约内容；多人研习室需要其他参与人员学号。
- 通用说明写 08:00–22:00、每次 1–4 小时，每人（含共同预约者）每天只能预约和使用一次。具体房间的起止时间以其接口和公告为准。
- 开始前 15 分钟内可以刷卡签到，前提是此前没有其他预约者。取消按开始前 15 分钟的时限办理，从“当前预约 → 研习室”查看可取消状态。
- 全部成员须按时刷卡签到；2–4 人间至少 2 人签到。开始 15 分钟后未达到最少人数，记申请人违约并释放预约；违约 3 次暂停预约 7 天。更大房间按自身人数配置，不把“至少 2 人”套到所有房型。
- 沪西有特别说明：预约人持本人一卡通，在预约开始前 10 分钟内到一楼咨询台办理签到和使用手续。
- 使用前检查设施，使用后恢复物品设备、带走个人物品及垃圾，关闭电源和房门。

预约时核对最新规则与最终成功页提示，签到按馆内要求由参与者完成。研修／考研座位的月度周期和连续未签到规则另见座位文档，不能与这里的小时制房间规则互换。

## 读取协议

均为 `https://space.tongji.edu.cn` 根路径的 POST 请求。复用 [座位文档](library-seats.md) 中浏览器同源认证方式；token 只在页面内使用。直接请求遇到证书链问题时可用 Chrome 同源读取。

| 用途 | 路径 | 请求／响应 |
| --- | --- | --- |
| 首页功能分类 | `/api/index/category` | 成功 `code:1`，`data` 列出首页入口；不是房间类型编号 |
| 研习室筛选配置 | `/reserve/index/index` | `{id:2}`；成功 `code:0`，`data.premises/storey/category/date/spaceTime/members` 等 |
| 快速选择的馆舍／楼层／房间 | `/reserve/index/quickSelect` | `id:2,date` 及当前筛选；成功 `code:0`，`data.area` 为房间资源，不能把“快速选择”名字理解为已创建预约 |
| 分页房间列表 | `/reserve/index/list` | `id:2,date,name,premisesIds,categoryIds,storeyIds,noiseId,boutiqueIds,startTime,endTime,members,size,page`；成功 `code:0`，`data.list/count/totalPage` |
| 房间详情 | `/reserve/index/detail` | `{id:2,areaId:<房间ID>,date}`；成功 `code:0`，`data.nameMerge,type_id,type_name,maxPerson,noise,boutique,contents,is_reducible` 等 |
| 房间组／人数信息 | `/api/Seminar/detail` | `{id:<房间ID>,day}`；成功 `code:1`，`data.children,membercount,upload,is_reducible`；不返回办公室联系人或完整个人字段 |
| 每日可约时间与限制 | `/api/Seminar/v1seminar` | `{room:<房间ID>,area:<当前页面building参数>}`；成功 `code:1`，`data.date`、`data.list[].date/info` |
| 申请表再次读取人数／时长 | `/api/Seminar/seminar` | `{room,area,day}`；成功 `code:1`，`minPerson,maxPerson,minTime,maxTime,isMouldShow,isSpaceUser,list` 等 |
| 使用规则 | `/api/index/booking_rules` | 成功 `code:1`；`data.seminar_declare/seminar_rule/discussion`，座位专门规则为 `study_Rules`，不要保存整包配置 |
| 目标时段的设备配置 | `/reserve/device/deviceInfoByTime` | 参数 `areaId,lang,startTime,endTime,day`。设备预约与设备控制分别处理 |

`area`／路由 `building` 的名字容易误导：例如嘉定202房间请求为 `{room:"44",area:"37"}`，37 是二楼资源编号，不是嘉定馆舍编号 1；沪西01为 `{room:"127",area:"21"}`，21 是二楼资源编号，馆舍为19。必须从当前详情／导航获得参数，不能将校区编号塞进去。

时间数据也有两层：`info.startTime/endTime/minTime/maxTime` 是分钟，例如 `510` 表示 08:30，`240` 表示最多 4 小时；`info.list` 是前端用于屏蔽的占用区间，其中 `beginNum/endNum` 可用分钟表达，其他同名时间字段可能是时间戳，不能混用。例如样例 `beginNum:840,endNum:930` 对应 14:00–15:30。只投影区间，不能输出预约者身份或预约记录编号。

不能单凭 `Fully_Booked:0` 就称目标时段可约：还需核实日期、开放边界、占用区间、最小／最大时长和 `is_reducible` 权限。时间页可能调整有效起点；开始等于结束时重新检查日期、可用区间和选择状态。房间 `maxPerson:"0"` 与“单人”名称并存时按配置异常／未明确人数处理，不能解释为能容纳零人。

其他房型可能使用 `/api/Room/detail` 月历读取及 `/api/Seminar/submit`、`roomConfirm` 等分支。遇到这些界面时观察实际请求和处理函数，补齐该房型流程。成员“添加”使用 `/api/Seminar/group` 取得成员资料，在预约需要且用户提供目标学工号时使用。

## 避免重复摸索

- 切换“座位”与“研习室”时，回首页点相应入口；**只把 `/SeatScreening/1` 改成 `/SeatScreening/2` 的哈希地址可能复用旧组件，标题和筛选仍停留在座位**。以实际“空间预约／请输入空间名称”等界面及请求 `id:2` 确认切换成功。
- 桌面“列表”有面板标题和可点击标签两个同名文字。当前标签定位为 `.filterContent > .header > .list`；不点击标题，也不使用过宽的 `.filterContent .list`，以免匹配多个元素。页面变化后重新核实结构，不凭索引强选。
- 列表默认 10 项，完整目录优先一次已知读取（例如 `size:100`）；不为列目录滚动遍历每个房间，也不拿第一间默认详情冒充用户目标。
- “预约规则”弹层点击内容不会关闭，官网使用遮罩外侧点击关闭；关闭后再操作底层，避免误点。不要为了阅读规则勾选协议或发出更新同意状态请求。
- 不固定等待每步网络完全空闲；等目标房间、选中日期或表单字段出现。发生接口／页面变化时只看当前实际加载的相关组件，不再次转储整个打包文件。

前端定位线索为 `SeatList`、`RoomDetail`、`seminarMakeCom`、`seminarUploadCom`，资源文件版本以当前页面为准。只提取相关导航、读取和提交处理函数；不输出浏览器存储、认证参数或完整申请人数据。
