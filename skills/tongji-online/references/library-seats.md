# 图书馆空位与选座预约

适用：查询某校区/楼层的当前空位，或在用户明确要求后预约一个座位。入口为 `https://space.tongji.edu.cn/h5/#/home`，与馆藏检索 `webpac.tongji.edu.cn` 是两个服务。使用浏览器流程和下列读取协议。研习室使用另一套房间流程，见 [研习室预约](library-study-rooms.md)，不要与“研修座位”混淆。

先按目标座位类型、馆舍和日期查询，名额、时段和闭馆时间从当前页面取得。

## 普通、研修、考研：共用界面，分别筛选

主页除“座位预约”外还有“研修座位”“考研座位”快捷入口，三者均属于 `/h5/#/SeatScreening/1` 的座位界面；界面的“座位类型”中可筛选普通座位、研修座位、考研座位。研习室主页入口则是 `/SeatScreening/2`，不能看成此处的第四种座位。

| 名称 | 首页分类编号 | 座位筛选 `categoryIds` | 预约特点 |
| --- | --- | --- | --- |
| 普通座位 | `1`（座位预约） | `["1"]` | 按日选座和签到 |
| 研修座位 | `6` | `["3"]` | 按馆舍公告选择使用周期 |
| 考研座位 | `7` | `["4"]` | 按考研季公告和资格办理 |

首页分类编号、请求 `id:1`、具体座位类型编号是不同层级。`/reserve/index/index` 的座位 `category` 实际返回 1/3/4；不把首页 6/7 发作筛选编号。类型是可多选项：已有研修勾选时再点考研会得到 `["3","4"]`，不会自动只剩考研。查普通空位时明确筛选 `["1"]`，不能把研修、考研的空位一起加总；先看当次勾选状态。

月度座位不能套用普通座位的“今天到闭馆”流程。官网“预约规则 → 研修专座”提供各馆规定（规则更新时间：2026-10）：

- **四平研修座位**：综合阅览楼一楼，全体在校师生，按月预约；每月倒数第二天 12:00 开放下一个自然月，不自动续期。规则写 24 小时开放；连续 3 天未签到释放，间隔 10 天后才能再次预约此类座位。
- **嘉定研修专座**：九楼阅览区，同样按月、每月倒数第二天 12:00 放下月名额。规则写连续 **2 天**未使用释放、间隔 10 天；不能错套四平的 3 天。签到方式为人脸入馆或九楼签到机；不可转借。
- **四平考研座位**：综合阅览楼二楼；当前公告是 **2026 年**考研季，9 月 23 日 8:00 起预约，使用至当年考研结束。公告称学号非 23 开头的备考学生需持考研证明到四平一楼咨询台登记；不据此自动判断本人资格，也不把该年份条件推广到以后。连续 3 天未签到释放、间隔 10 天后可再约。

研修和考研按当前公告、资格及可选周期继续办理；进入其选位页面后核对对应提交处理函数，普通座位的 `/api/Seat/confirm` 仅用于普通选座链路。

## 最短流程

1. 读本文件，确定校区、楼层、日期。只问缺失且影响结果的条件；“四人桌的位子”是预约其中一个座位。用户未指定结束时间时，可在读取空位的同时询问；“到闭馆”需要从当天可选时段确认终点。
2. 复用已有可控且已登录的空间预约页面；没有时启动一个浏览器上下文，恢复本地学校认证，打开官方入口。遵循宿主当前的浏览器执行权限。
3. 在已认证页面内读取区域列表，按校区、楼层筛选并汇总 `free_num`。只问空位时到这里就可回答，附查询时间，不必加载每个座位或平面图。
4. 需要预约时，在同一页面选择“座位预约 → 日期 → 馆舍 → 楼层 → 区域 → 确定选择”。核实当天的起止时间。初次判断桌型时查看一次“平面图”；接着切换“列表模式”，选一个仍可用的座位编号。
5. 核对页面的日期、起止时间、区域、已选座位号。用户授权已覆盖这些条件时，点击一次“立即预约”，等待明确的成功或失败提示。
6. 成功页提供地点、座位、时间且显示“预约成功”即可作为完成证据，保存必要截图并汇报。只有结果含糊、或还需核实签到截止时间时，再读取一次本人当前预约。结束后关闭临时浏览器并释放状态锁。

关键效率点：查询和预约使用同一个浏览器上下文；只对目标区域查看布局；用座位列表精确选择，避免在缩小的地图上反复点坐标；成功证据齐全后停止验证。

## 认证与连接方式

- 优先复用本地学校统一身份认证，允许学校页面自动跳转；只有页面要求本人操作时才请用户扫码或手动输入密码，不把密码交给模型。
- 空间网站在 `sessionStorage.token` 中维护自己的登录凭据。只在本地程序/页面内使用，不输出、截图或复制到对话中。检查是否登录时只返回布尔值；凭据存在仍需由业务读取成功确认有效。
- 当前脚本的 `withBrowser(options, action)` 可恢复保存的学校 Cookie 与本地存储，并在回调结束时关闭浏览器。它不是连接用户日常 Chrome 的个人配置。需要持续查询和点击时，让回调和进程保持运行，在同一 `context` 中完成操作，不每个步骤都重新调用。
- `withBrowser` 会持有 `TONGJI_ONLINE_HOME` 的状态锁；浏览器流程未结束时不要并行启动使用同一目录的登录/查询进程。
- 此网站的 token 位于会话存储；当前通用保存逻辑不自动持久化这项空间网站凭据。保持一次任务的会话连续，重启后从官方入口恢复认证。
- 直接请求遇到 `UNABLE_TO_VERIFY_LEAF_SIGNATURE` 而 Chrome 正常时，改用已认证页面的同源 `fetch`。证书链问题按连接问题处理，保留证书校验。

只把页面内读取结果中的业务字段返回给模型。按允许字段输出比“删除部分敏感键后返回整个响应”更可靠。不要输出完整浏览器存储、请求头、认证跳转地址或响应日志。

## 读取接口

以下相对路径均属于 `https://space.tongji.edu.cn`，方法均为 POST。不同接口的成功码不同，不能统一判断。

| 用途 | 路径 | 请求字段 | 成功响应 |
| --- | --- | --- | --- |
| 日期/馆舍/楼层筛选配置 | `/reserve/index/index` | `{id:1}` | `code:0` |
| 普通座位的区域列表 | `/reserve/index/list` | `{id:1,date,categoryIds:["1"],premisesIds:[馆舍ID],size:100,page:1}` | `code:0`，`data.list`、`data.count` |
| 指定区域详情 | `/reserve/index/detail` | `{id:1,areaId,date}` | `code:0`，`data` |
| 区域可预约日期和时段 | `/api/Seat/date` | `{build_id:区域ID}` | `code:1`，`data` 中每一天含 `times` |
| 对应时段的座位状态 | `/api/Seat/seat` | `{area:区域ID,segment:时段ID,day,startTime,endTime}` | `code:1`，`data` 为座位数组 |

`id:1` 表示座位业务入口，包含普通、研修、考研。区域列表可用 `categoryIds:["1"]` 明确限定普通座位，研修／考研按上表分别筛选。`date`/`day` 使用学校当地日期 `YYYY-MM-DD`；时段 ID、起止时间必须来自当前 `/api/Seat/date` 结果。前端选择 `status==1` 且 `start<end` 的可用时段，座位列表可选项为 `status==1 && in_label==1`。座位显示编号与后台 `id` 不同，不相互代替。

区域列表应按实际返回的 `premisesName`、`storeyName`、`nameMerge` 识别校区和楼层；汇总匹配区域的 `free_num`，保留区域明细。先检查分页是否完整：未覆盖 `data.count` 时读取剩余页，或明确只是部分结果，不能把第一页当作全馆。缺字段、错误响应不解释成零空位。`free_num` 表示当前空闲数，未来预约按目标时段读取。

页面内读取的协议要点（按目标接口选择对应参数及响应投影）：

```javascript
// 在已登录的空间预约页面中执行；凭据不作为参数返回给宿主或模型。
const result = await page.evaluate(async ({ path, data }) => {
  if (location.origin !== 'https://space.tongji.edu.cn') throw new Error('WRONG_ORIGIN');
  const token = sessionStorage.getItem('token');
  if (!token) throw new Error('LOGIN_REQUIRED');
  const authorization = 'bearer' + token; // 当前官方前端无空格，不能改成常见的 Bearer + 空格。
  const response = await fetch(path, {
    method: 'POST', credentials: 'same-origin', redirect: 'error',
    headers: { 'Content-Type': 'application/json', 'X-Requested-With': 'XMLHttpRequest', authorization },
    body: JSON.stringify({ ...data, authorization })
  });
  if (!response.ok) throw new Error('SEAT_READ_REJECTED');
  const body = await response.json();
  if (body.code !== 0 || !Array.isArray(body.data?.list)) throw new Error('SEAT_SCHEMA_CHANGED');
  // 此投影仅适用于区域列表；其他接口应使用各自的结构和成功码。
  return { count: body.data.count, rooms: body.data.list.map(r => ({
    id: r.id, name: r.name, nameMerge: r.nameMerge,
    premisesName: r.premisesName, storeyName: r.storeyName,
    total: r.total_num, free: r.free_num
  })) };
}, { path, data });
```

区域树使用 `/reserve/index/index` 与 `/reserve/index/quickSelect`；旧 `/api/Seat/tree` 已失效。核对个人预约从网站“当前预约”进入，按页面实际请求取得记录。

以下为公共区域编号，使用前与当前目录核对：

| 区域 | 后台区域 ID | 目录座位数 |
| --- | --- | --- |
| 六楼阅览区-北 | 128 | 48 |
| 六楼阅览区-西 | 129 | 64 |
| 六楼边桌区-北 | 3 | 15 |
| 六楼边桌区-西 | 10 | 17 |

嘉定馆舍 ID 为 `1`。六楼筛选配置与实际楼层字段有不同编号，使用官网返回值或可见文字，不把“六楼”转换成数字 `6` 当作接口 ID。

用平面图判断桌型和位置，再从实时座位列表选位；只对目标区域查看布局。

“四人桌”偏好：先在四人桌组中选一个可用位；若没有，再按用户已允许的中间位置筛选，不把旁边三个座位一并预约。若布局证据不足，只说具体区域或中间位置，不承诺桌型。

## 页面等待、提交与结果核对

- 应用使用带 `#` 的前端路由。从官网首页筛选进入；需要直达时使用当前页面实际生成的路由和参数。
- 点击后页面可能短暂保留旧内容。等待目标文字/控件状态，例如当前选中编号或“预约成功”，再读取相关区域；不对每个点击都强制等全页 `networkidle`（网络完全空闲）并转储整页。只在缺少目标元素或页面变化时取一次完整快照。
- “查看平面图”会打开遮罩。查看后先关闭，再切“列表模式”；防止在遮罩未消失时误点底层。重复文字应限定到目标面板/弹窗，不随意使用 `.first()` 或索引选中。
- 普通座位“立即预约”由官方前端调用 `/api/Seat/confirm`，提交已选座位的后台 ID 和时段 ID，并经过官方加密处理。**通过可见按钮提交，不仿造该写入请求，不复用研习室的 `/reserve/index/confirm`。**
- 点击一次后等结果。出现“正在预约”不代表失败；请求超时或页面结果不明时，先查看本人预约状态，无法确认就汇报“不确定是否成功”，不要再次提交或换座造成重复操作。
- 只有明确失败、确认未产生预约且用户偏好仍覆盖新选择时，才重新选位。取消已有预约、签到或处理违约需要对应用户任务。
- 成功截图中的实际起始时间可能晚于最初展示的时段起点，以最终成功页面/预约记录为准。
- 汇报地点、座位、日期、实际起止时间，以及页面明确显示的签到截止要求。未显示签到时限就说明未获得，不凭经验补一个“15 分钟”或“30 分钟”。保存必要的成功截图后停止；用户拒绝进一步读取时不重试。

## 高效查询与继续探索

先复用本文件的入口和读取协议，按用户目标缩小到馆舍、楼层和类型。页面或字段变化时，观察当前请求并提取相关前端函数；将新参数、成功标准和有实际影响的差异补回文档。查询和预约复用一个浏览器上下文，取得完整结果后即可结束。
