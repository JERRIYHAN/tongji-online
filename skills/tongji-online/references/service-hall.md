# 一网通办：办事大厅与校园服务导航

用户不确定校园事务在哪个系统办理，或要找一卡通、学工、班车、网络、软件、图书资源等入口时，先查本文件。具体服务名称和负责单位查 [完整事项目录](service-hall-catalog.md)，不要重新逐个点击分类。已有 Canvas、教务、图书馆等适配时，定位后直接转相应子文档，不绕回门户重复登录。

## 入口与认证

官方入口：`https://all.tongji.edu.cn/new/index.html#/`，页面名称“办事大厅”，页头“同济大学@一网通办”。通过官网复用学校统一认证；当前 CLI 没有独立门户服务，浏览器任务保持同一上下文。

目录更新于 2026-10，包含 317 项服务、254 项在线办理事项，覆盖学生、研究生、教职工和管理角色。按事项名称定位后，在目标页面核对适用身份与办理期。

## 下次使用与避免绕路

1. 先按常见需求表或完整事项目录匹配名称。已知目标系统且已有适配流程时直接去目标系统；只有需要搜索未知业务时才打开门户。
2. 需要门户时复用学校认证，并等待内嵌主体中的“服务分类”等目标栏目出现。外层页面的可访问性快照可能只有 `iframe`，不代表空站点或登录失败；应在实际内容 frame 内读取。
3. 查询目录优先读取首页已加载的全分类响应，不逐个点击 16 个分类。首页只显示常用/推荐的一部分条目，还有“更多”，不能将可见卡片数当作全部事项数。
4. 用户真正需要具体服务时，按名称在当前全站搜索框搜索，或由分类定位事项，再读取办事指南和目标入口。不要把收藏星标、推荐设置或“在线办理”当作展开菜单。用户只要查询时不提交申请、签章、缴费、评价或发送反馈。
5. 门户目录并非所有链接都新：如自助服务仍指向旧版图书借阅地址，而已验证图书馆适配使用 webpac 新版检索；校历快捷链接也不等于教务真实菜单路由。门户是定位线索，目标站点以对应 skill 子文档和当前官网结果为准。
6. 服务入口或权限变化时刷新相关元数据；认证码、Cookie、带一次性票据的跳转链接不进入聊天或文档。导航成功不等于业务完成。

## 目录读取与刷新线索

已观察到的门户读取入口：

| 请求 | 作用及边界 |
| --- | --- |
| GET `/getUserPermissionRouters` | 站点级可见入口；不是 317 项服务清单 |
| GET `/getPageView` | 当前页面导航和配置；只提取 `data.pageContext.treeMenu` 等导航字段，完整响应还含其他不必输出的数据 |
| POST `/execCardMethod/<当前卡片wid>/SYS_CARD_SERVICEITEMCATEGORYDETAIL` | 根据请求体 `method` 区分分类配置与事项列表；同一 URL 的不同响应不能混用 |
| POST `/execTemplateMethod` | 多种模板方法共用的分发入口，按请求体方法和分类区分用途 |

事项列表的已验证读取方法是 `queryItemByCategoryList`，全分类请求参数为 `allCategory:"1"`、`categoryWid:"all"`、空 `searchKey`、`pageNumber:1`、`pageSize:1000`，返回外层 `errcode:"0"`，内层 `data.errcode:"0"`，数组在 `data.data`，总数在 `data.totalSize`。页面的角色列表及其他筛选条件来自当前配置，刷新时复用实际页面请求，不硬编码个人或角色身份，也不为求全放宽权限。默认目录已经包含多种角色入口，读取这些元数据不是授权办理它们。

卡片编号从当前页面配置取得。先等首页全分类响应完成，再按“路径 + 请求体 method + 分类条件”识别响应；不能仅按 URL 缓存最后一条，否则点击分类后会把局部列表当全量。检查条数、总数及 `itemWid` 去重，分页未完整时继续读取当前协议的后续页或明确标注范围，不能声称完整。

仅保留 `itemWid`、`itemName`、`itemDept`、`itemCategory`、必要业务状态字段；不要保存收藏、访问历史、待办、个人卡片数据或完整响应。`itemWid` 是公共目录事项标识，不是用户学号；不要按“长数字”统一脱敏而破坏事项 ID 和正常目标地址。敏感数据应按来源与字段排除。

前端定位：外层当前加载的 `app.*.js`，内嵌模板 `/CUS_TEMPLATE_TONGJI/pc/index.html`，全部事项组件 `/CUS_CARD_TJQBSX/pc/js/app.js`，特色组件 `/CUS_CARD_TJ_TSFW/pc/js/app.js`。其中 `getCategoryDetail`、`queryItemByCategoryList` 可帮助核对读取协议。资源版本与卡片配置可变，使用当前资源版本。只按函数提取相关片段，不重新分析整个组件库。

需要新服务时从当前目录、办事指南和目标网页继续探索，记录公共入口与读取协议。共用分发地址的不同方法分别确认用途。
